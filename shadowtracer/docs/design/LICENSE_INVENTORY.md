## 3. How ShadowTracer's own code communicates with GPL code

**Confirmed by reading the code, not assumed**: zero direct imports. Grepped every
`.py` file under `shadowtracer/ingest`, `shadowtracer/correlate`, and
`shadowtracer/console/backend` for `import framework`/`from framework` (the GPLv2
Wazuh Python API) and for any `subprocess`/manager-API call (port 55000, Wazuh's REST
API) - zero matches in all three. The only two integration points are:

- **Files**: the shipper tails `alerts.json`/`archives.json`, plain text files the GPL
  manager writes - read-only, no linking, no shared process memory.
- **Network**: Kafka (`shadowtracer.events.raw`), a message queue both sides connect
  to as independent clients - again no linking.

This is the cleanest boundary available short of running on entirely separate
machines - it's a process/file/network boundary throughout, never a library-linking
one, which is the thing GPL's "derivative work" question actually turns on. **Still
flag for a lawyer**: this inventory states the technical boundary as found; whether
that boundary is sufficient to keep ShadowTracer's own console/ingest/correlate code
GPL-unencumbered is a legal conclusion this doc does not make.

## 4. Obligations when shipping (not legal conclusions - a checklist for one)

- **GPLv2 (Wazuh base)**: source availability for the GPL-covered parts (the forked
  `src/`/`framework/`/`ruleset/` code) to anyone who receives the binary - standard
  GPLv2 term, applies regardless of how ShadowTracer's own code is licensed, because
  of §1's SSLeay-in-a-GPL-file finding and the ruleset's own GPLv2 header.
- **LGPL (psycopg2-binary)**: see §2's flag - confirm the static-bundling question
  before shipping.
- **DRL 1.1 (Sigma rules, if/when vendored)**: attribution notice for SigmaHQ; check
  DRL 1.1's exact share-alike terms for any *modified* rule before shipping one.
- **MPL-2.0 (certifi, lightningcss)**: file-level share-alike only triggers on
  redistributing a *modified* copy of the MPL-covered file itself - not triggered by
  normal use as an unmodified dependency, per general MPL-2.0 practice; **still a
  lawyer question**, not asserted as fact here.
- **Attribution/NOTICE file**: this repo does not currently have a consolidated
  third-party NOTICE file enumerating every dependency's licence - shipping a binary
  distribution (not just source) typically expects one; not built here, flagged as a
  gap.
- **Nothing in this inventory found a licence that outright blocks shipping** a
  commercial product (no AGPL, no "no commercial use" terms anywhere in either
  dependency tree) - the real open questions are all about *how* obligations are met
  (attribution, source availability, the LGPL static-linking point), not *whether*
  shipping is possible at all.
